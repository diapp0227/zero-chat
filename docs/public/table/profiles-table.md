# DynamoDB テーブル定義: `zero-chat-profiles`

サインインした人のプロフィール (ユーザー名・役職・アバターの色) を保存するテーブル。1 人 1 項目。
Cognito のユーザーと、ユーザーの番号 (`sub`) で結び付ける。

## テーブル

| 項目 | 値 |
|---|---|
| テーブル名 | `zero-chat-profiles` |
| リージョン | `ap-northeast-1` (東京) |
| パーティションキー | `userId` (文字列) |
| ソートキー | なし |
| キャパシティモード | オンデマンド |
| グローバルセカンダリインデックス | なし (自分のプロフィールを `userId` で 1 件読むだけなので不要) |

## 項目 (1 人分) の属性

| 属性 | 型 | 必須 | 説明 |
|---|---|---|---|
| `userId` | 文字列 (S) | ○ | Cognito ユーザープールのユーザーの番号 (`sub`。例: `1a2b3c4d-...`)。テーブルのパーティションキー |
| `name` | 文字列 (S) | ○ | ユーザー名。前後の空白を除いて 1〜30 文字 |
| `role` | 文字列 (S) | ○ | 役職 (`エンジニア` / `デザイナー` / `プロダクトマネージャー` / `セールス` / `コーポレート`) |
| `color1` | 文字列 (S) | ○ | カラー1。アバターのグラデーションの開始色。`#RRGGBB` (大文字。例: `#E8BD79`) |
| `color2` | 文字列 (S) | ○ | カラー2。アバターのグラデーションの終了色。形は `color1` と同じ |
| `updatedAt` | 文字列 (S) | ○ | 最後に保存した日時。UTC の ISO 8601 形式 (例: `2026-10-16T09:00:00Z`) |

### カラーを `#RRGGBB` の文字列にしている理由

- Web の色の書き方と同じなので、DynamoDB のコンソールで見ても色がわかる
- Figma のプロフィール設定画面も、色を `#E8BD79` の形で表示している
- 透明度は使わないので、`#AARRGGBB` ではなく 6 桁にしている。アプリは不透明 (`FF`) の色として読む

カラー1・カラー2 を 1 つのマップやリストにまとめず、別々の属性にしているのは、
項目が 2 つだけで、画面でも「カラー1」「カラー2」と別々に選ぶため。

### `userId` に Cognito の `sub` を使う理由

- `sub` はユーザープールの中でユーザーごとに一意で、**あとから変わらない**
  (メールアドレスは変えられるので、キーにすると変更のたびに項目を移す必要がある)
- API Gateway の JWT オーソライザーが確かめたトークンに入っているので、
  Lambda はアプリから送られた値ではなく、トークンから自分の番号を取れる (他人のプロフィールを書き換えられない)

## 項目の例

```json
{
  "userId": "1a2b3c4d-1111-2222-3333-444455556666",
  "name": "ああああ",
  "role": "デザイナー",
  "color1": "#E8BD79",
  "color2": "#B87947",
  "updatedAt": "2026-10-16T09:00:00Z"
}
```

## Flutter のモデルとの対応

| DynamoDB | Flutter (`lib/domain/models/profile.dart`) |
|---|---|
| 項目 (1 人分) | `Profile` |
| `name` | `Profile.name` |
| `role` | `Profile.role` |
| `color1` | `Profile.color1` (`Color`) |
| `color2` | `Profile.color2` (`Color`) |
| `userId` | なし (API がトークンから決める。レスポンスにも含めない) |
| `updatedAt` | なし (今は表示しない) |

## 今後の課題

- **カラーの設定画面**: 色は保存できるが、アプリにはまだ色を選ぶ画面がない。
  サインアップ時は決まった色 (`#E8BD79`・`#B87947`) を保存する
- **投稿とのつながり**: 投稿・返信の `author.userId` にこのテーブルのキーを入れている。
  投稿の取得 API が最新のプロフィールで表示するので、プロフィールを変えると過去の投稿・返信の表示も変わる
  (`userId` を保存する前に作った投稿・返信は除く)
